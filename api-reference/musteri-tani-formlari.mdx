Müşteri tanı formları (Accord doğrulama kayıtları), müşterinin kimlik ve KYC bilgilerinin toplandığı resmi kayıtlardır. Bireysel ve kurumsal (temsilci/ortak/gerçek faydalanıcı + kurumsal belgeler) akışlar desteklenir.

## `POST /v1/customers/verifications` — form oluşturma

Müşteri tanı (KYC) formu açar; kayıt onay bekleyen doğar (`isApproval: false`) ve onay akışı panel tarafında tamamlanır. API üzerinden doğrudan onaylı müşteri yaratılamaz. Aynı `idNo` ile onay bekleyen form varsa `409 CONFLICT` döner (`details[0].existingId` mevcut formu gösterir).

### İstek gövdesi

```json
{
  "data": {
    "idNo": "12345678901",
    "nameSurname": "ÖRNEK KUYUMCULUK A.Ş.",
    "idType": "company",
    "idCardType": "idCard",
    "customerRelation": {
      "types": "representative",
      "nameSurname": "Yetkili Adı",
      "idNo": "98765432109"
    },
    "companyDocuments": {
      "taxDoc": { "fileName": "vergi-levhasi.pdf", "mimeType": "application/pdf", "content": "JVBERi0x..." }
    }
  }
}
```

Temel alan kuralları [hızlı cari ekleme](/api-reference/musteriler) ile aynıdır; ek olarak:

| Alan | Tür | Kural |
|---|---|---|
| `onlyInvoice` | boolean | Formu yalnız fatura kaydı olarak açar |
| `customerRelation` | object | Yalnız `idType=company` — temsilci/ortak/gerçek faydalanıcı |
| `companyDocuments` | object | Yalnız `idType=company` — `taxDoc`, `activeDoc`, `registryDoc`, `signDoc` |

<Note>
  Kurumsal belgeler Accord akışıyla aynı doğrulamadan geçer: PDF/JPEG/PNG, belge başına en fazla 2 MiB, dosya uzantısı ve içerik imzası MIME türüyle eşleşmeli. İçerik güvenli geçici depoya yazılır ve panel onayında kimlik servisine taşınır. Kimlik/pasaport görselleri için [Kimlik belgeleri](/api-reference/kimlik-belgeleri) ucu kullanılır.
</Note>

### Cevap — `201`

Oluşan formun liste öğesi döner (`id`, `idNo`, `nameSurname`, `isApproval: false`, `masakStatus` vb.); durum takibi `GET /v1/customers/verifications/{id}` ile yapılır.

## `GET /v1/customers/verifications` — form listesi

### Sorgu parametreleri

Ortak parametreler için [Genel Bakış](/api-reference/genel-bakis).

| Parametre | Tür | Açıklama |
|---|---|---|
| `filter[idNo]` | string | TCKN/VKN tam eşleşme |
| `filter[idType]` | string | `person` veya `company` |
| `filter[idCardType]` | string | `idCard`, `passport`, `dlCard`, `other` (legacy kapsamalı) |
| `filter[isApproval]` | boolean | Form onay durumu |
| `filter[isSigned]` | boolean | İmza durumu |
| `filter[isDeleted]` | boolean | Verilmezse yalnız **silinmemiş** formlar döner |
| `filter[masakStatus]` | integer | `0` sorgulanmadı, `1` sorun yok, `2` sorunlu |
| `filter[startDate]` / `filter[endDate]` | date-time | `createdAt` aralığı |
| `filter[updatedSince]` | date-time | Artımlı senkronizasyon |
| `q` | string | Numerikse `idNo`, metinse ünvan araması |

Sıralama whitelist'i: `createdAt`, `updatedAt`, `nameSurname`. Varsayılan `createdAt:asc`.

### Cevap alanları (liste öğesi)

`id`, `idNo`, `idType`, `idCardType`, `nameSurname`, `phone`, `email`, `nationality`, `countries`, `states`, `cities`, `masakStatus`, `isApproval`, `isSigned`, `onlyInvoice`, `contractVersion`, `createdAt`, `updatedAt`

## `GET /v1/customers/verifications/{id}` — form detayı

Liste alanlarına ek olarak:

| Alan grubu | İçerik |
|---|---|
| Kimlik/iletişim | `birthplace`, `birthday`, `phone2`, `taxOffice`, `registryNo`, `activityName`, `naceCode`, `iban`, `address`, `motherName`, `fatherName`, `isAbroad`, `jobName` |
| `customerRelation` | Kurumsal kayıtta temsilci/ortak/gerçek faydalanıcı (`representative`, `shareholder`, `beneficialOwner`) |
| `companyDocuments` | Kurumsal belgelerin **metası** — `fileName`, `mimeType`, `size` (içerik dönmez) |
| `requirementsSnapshot` | Formun doldurulduğu andaki zorunluluk ayarlarının anlık görüntüsü |
| `isDeleted` | Formun silinme durumu (detayda görünür) |

<Warning>
  Form görselleri ve belge içerikleri (`frontImage`, `signatureImage`, `addressDoc` vb.), SMS kodları ve onay kilidi gibi iç alanlar hiçbir uçta dönmez.
</Warning>
